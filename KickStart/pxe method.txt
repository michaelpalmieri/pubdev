Download

Step 8 Configure PXE Menu

Create

/srv/tftp/pxelinux.cfg/default

Example

DEFAULT ESXI

LABEL ESXI

APPEND -c http://192.168.10.10/esxi/boot.cfg

For UEFI, you may instead boot directly with BOOTX64.EFI and provide the appropriate boot.cfg location, depending on your PXE stack (plain TFTP, iPXE, etc.).

Step 9 Modify boot.cfg

Find

kernelopt=

Original

kernelopt=runweasel

Change

kernelopt=runweasel \
cpuUniformityHardCheckPanic=FALSE \
ks=http://192.168.10.10/kickstart/esx01.cfg
Step 10 Create Kickstart
/var/www/html/kickstart/esx01.cfg

Example

vmaccepteula

--bootproto=static \

Deploying Multiple Servers

This is where PXE shines.

Instead of modifying boot.cfg for each host, use a different PXE configuration per MAC address.

Example

3C:EC:EF:AA:01:11

↓

boot-esx01.cfg

↓

ks=http://192.168.10.10/kickstart/esx01.cfg

Another server

3C:EC:EF:AA:01:12

↓

boot-esx02.cfg

↓

ks=http://192.168.10.10/kickstart/esx02.cfg

Each host receives its own boot configuration automatically based on its MAC address.

Scaling to 100+ Hosts

Rather than creating many boot.cfg files, a common enterprise pattern is:

One boot.cfg

↓

One ks.cfg

↓

%pre script

↓

Reads MAC Address

↓

Downloads correct host configuration

↓

Installs

This means:

One ESXi installer
One PXE menu
One Kickstart entry point
Unlimited hosts

The %pre script determines which host is booting and fetches the appropriate configuration dynamically. This is the approach used in many large VMware environments because adding a new server only requires updating an inventory (CSV, database, or web service), not creating new boot menus.
