Run a script that generates esx01.cfg, esx02.cfg, etc.

Step 2 Create the Template

Template.cfg

vmaccepteula

rootpw {{RootPassword}}

install --firstdisk=local --overwritevmfs

network \
--bootproto=static \
--device=vmnic0 \
--ip={{IPAddress}} \
--netmask={{SubnetMask}} \
--gateway={{Gateway}} \
--hostname={{Hostname}}.lab.local \
--nameserver={{DNS}} \
--vlanid={{VLAN}}

reboot

%firstboot --interpreter=busybox

esxcli system hostname set \
--host {{Hostname}} \
--domain lab.local

esxcli system ntp set \
--server={{NTP}}

esxcli system ntp set \
--enabled=true

/etc/init.d/ntpd restart

vim-cmd hostsvc/enable_ssh
vim-cmd hostsvc/start_ssh

Everything inside {{ }} is replaced by the script.

Step 3 PowerShell Generator

Save as Generate-Kickstart.ps1

$Template = Get-Content ".\Template.cfg" -Raw

$Hosts = Import-Csv ".\Hosts.csv"

foreach ($Host in $Hosts)
{
    $Config = $Template

    $Host.PSObject.Properties | ForEach-Object {
        $Config = $Config.Replace("{{{0}}}" -f $_.Name, $_.Value)
    }

    $OutputFile = ".\Output\$($Host.Hostname).cfg"

    $Config | Out-File $OutputFile -Encoding ASCII
}

Scaling to Hundreds of Hosts

As your environment grows, you can expand the CSV to include nearly every per-host setting you care about. For example:

Hostname,IPAddress,SubnetMask,Gateway,DNS,VLAN,NTP,RootPassword,InstallDisk,Domain,VMotionIP,VSANIP,LicenseKey
esx01,192.168.10.21,255.255.255.0,192.168.10.1,192.168.10.5,120,192.168.10.5,VMware123!,naa.600...,lab.local,192.168.20.21,192.168.30.21,XXXXX-XXXXX-XXXXX-XXXXX-XXXXX

Your PowerShell script can then replace additional placeholders such as {{InstallDisk}}, {{Domain}}, or {{LicenseKey}} in the template. This gives you a single source of truth: update the CSV, regenerate the Kickstart files, and every host configuration stays consistent.

A couple of production improvements

For a production deployment, I'd make two changes to the example above:

Don't store the root password in plain text. Generate an encrypted password hash with openssl passwd -6 (or another supported method) and use rootpw --iscrypted in the template.
Add validation to the PowerShell script. Before generating files, verify that there are no duplicate hostnames or IP addresses and that all required fields are populated. Catching those mistakes before deployment saves a lot of troubleshooting later.

This CSV + template approach is straightforward to maintain and scales well from a handful of hosts to hundreds without having to hand-edit individual Kickstart files.
